# Fidelity: app screens against `docs/specs/mobile-prototype.html`

Phone shots come from `ConnectScreensTest` (CPH2417, Android 15, dark and light, 2026-10-11), compared with headless-Chrome renders of the prototype.

| Screen | State | Differences |
|---|---|---|
| connect | checked, dark and light | none seen |
| permission (ask, blocked) | checked | the blocked screen is drawn from a flag: adb cannot revoke the permission on this ROM, so it was not reached by hand |
| scan (camera A), paste sheet | checked with a stand-in feed | the real camera preview and the torch were not tried by hand; the prototype's "maqueta: leer QR" is not shipped |
| pairing | checked | "(60 s)" is not drawn (no number to take it from); "PC alcanzado" only once the socket opened; the spinner glyph is smaller than the prototype's |
| denied, expired, limited | checked | none seen |
| no encuentro tu PC | checked | rows drawn only when measured (see `SPEC-NOTES.md`); "reintentar" is not drawn |
| protocol | checked, both sides | the numbers are the real ones |
| workspaces (home) | checked, dark | search built (name, branch, path); singular "workspace · 1"; legend glyphs in their colours. **Not done:** `+` (needs server messages `open{path}` and `worktree{...}`, "W4"), the row's second line is the branch and PR, not the agent's last message (the bridge does not send it), the current-row highlight (no notion of "current" on the wire), ⚑ merged (needs GitHub data) |
| settings | checked, dark | quick answers as three presets with the preview line; themes as a **read-only** grid (the user chose: the app follows the system theme and nothing writes `settings.json`); connection rows show the host, the real protocol number and access, no latency (not measured), no PC name (`ready` does not send one); the prototype's animation and vibration toggles are not built (no feature behind them) |
| workspace | checked on a phone (Android 16): terminal, key row, composer, leader sheet, split, close pane, selection and copy, fit-to-phone on and off (the pane read 126×55 again) | `^␣ n` (name) and esc/^C from the key row not tried. **y and n tried against a real Claude Code permission prompt** (the `run` pane of the test daemon, `--permission-mode default`, hooks as jw installs them): the pane showed `waiting`, the ask bar enabled; `y` ran the command, `n` did not; the dialog drew in full, in colour. Seen: after `n` the daemon goes on saying `waiting` (claude fires no hook when a prompt is refused, so jw has no event to leave the state with), and the bar stays until the next hook; the TUI reads the same state |

| diff (changes) | checked on a phone (Android 16), dark, against a repo with 303 changed files, 3 unpushed commits, a modified, a deleted, an untracked, a binary and a symlinked file | the three views, the commit list with `◂ ▸`, a file's hunks with line numbers, the marks `A M D R ?`, the unreadable reason, "viewed". The marks were checked: they redraw in the list and from a file's header, persist after the app is stopped, and one resets when its file is edited (REQ-74); a binary shows "binario"; a symlink shows its reason and its target never arrives. **Also checked on the device, against repos under `/tmp/jwt`:** too large (a 3 MiB file in a commit: the list of names, no counts, no marks, "demasiado grande"), no base (an origin with no default branch, and a repo with no origin: the note in General and, in Commits, the note that these are `HEAD`'s commits), and an error of a view (a folder that is not a repo: the reason with the workspace's name, never its path, `General !`, ERR, and "reintentar" found the repo once it existed). **Not tried:** a light theme, a long line wrapped. **Differs from the TUI on purpose:** no changed-word marks, a too-large view only lists, "viewed" is kept on the phone and resets when the file changes |
| touch targets (REQ-26) | measured on the phone (`TouchTargetsTest`, 12 steps through home, search, the sessions sheet, avisos, settings, a workspace, the leader sheet, the finder, changes in its three views): every pressable is 48 dp or more | Before the change the same walk listed more than 50 entries (the output was cut there) at 36 to 44 dp, among them the key row (38), the pane tabs (40), the composer and the y/n buttons (44). The key row's padding lost 5 dp so it is as tall as it was. Not covered by the test: the scan and pairing screens, drawn by `ConnectScreensTest` |
