The shell as blocks, in the terminal and on the phone

One model, two screens. The terminal draws today's jw layout with each shell pane as a rounded box of command blocks; the phone draws the same blocks flat, with the pane tabs and an editor. Both read the same data: run a command in one and it appears in the other, and what you look at clears on both. Click the terminal or tab into it; the keys are on its status bar.

  1. When the daemon restarts the history stays (button «The daemon restarts»). Each shell pane's blocks are saved on disk by the daemon and come back with it: the last 100 blocks and no more than 4 MiB of them for each pane, the oldest going first. A line across the pane says el daemon se reinició and the time: what is above it was kept, what is below it is new, in the terminal and on the phone. A command that was running is kept as interrumpido with the time it had run, in grey, because its end was never seen; a program that had the whole screen (claude, nvim) is gone and the pane is the shell again, as today. The prompt starts empty. clear empties the saved history too.

The shell as blocks (the terminal's version of what the phone prototype already does): inside a shell pane's box, each command is a block with its folder, branch and time, a bar at the left (green done, red failed, yellow running), bold command and its coloured output; newest at the bottom.   7. The field at the foot (changed) is drawn as the phone's today, which is flat: no box, a band of its own colour under the blocks. On it, a row of chips (the folder and, when there is one, ⎇ branch, each a pill; while a command runs, ◌ and the command in yellow), and under it the line: the green ❯, the text you type, and the blue send mark ➤ at the right. With nothing typed it says «escribe un comando»; while something runs it says «va al programa» (the phone's longer «lo que escribas va al programa» does not fit a narrow pane) and a red ■ ^C sits beside the send mark (the phone's red stop beside its send). The band has room around it, as the phone's has: a free row over the chips, one between the chips and the line, one under the line, and a column of margin at each side (five rows in all, where the old editor took three). A line longer than the line wraps under it and the band grows, up to five rows of text. The shell still owns the line (history, tab and its key bindings work as today): the client draws what the shell has typed, after its prompt. For that the daemon has to say where the typed text starts: one optional field in the blocks node (the cursor at the shell's prompt-end mark), which is also what mirroring the line on the phone (OPEN-6) needs. Without it, only the band, the chips and the marks could change, not the text or the placeholder.

  8. A program that takes the screen (new): when a command that draws its own screen starts (claude), the pane no longer shows the shell's screen as it was while the program has not painted anything. The box says «iniciando claude…» with a spinner (and the phone the same, with «toca ■ para cancelar»), and the moment the program paints, the screen is drawn as it is. When the program ends the blocks come back. It is the same for any program that takes the screen (claude, nvim, mole, htop, lazygit, fzf…): the name in «iniciando …» and «cerrando …» is the command's own, and pick one in the list above to see it. On the way out (new): a program that leaves its screen and takes a moment to finish (claude, about a second; nvim or htop, a moment) no longer shows the shell's own screen under it (the terminal as it was, with your prompt): the same spinner says «cerrando claude…» until the blocks return. Press claude exits to see it: the screen goes, the loading shows for about a second, then the blocks. Try Start claude and claude exits above; in the terminal ^C still cancels. The daemon says when the program has painted: its running block has output (out) from then on, which is also what keeps the loading from showing for a program that paints at once (nvim: a screen of its own, no loading).

  9. On the phone the same blocks are drawn flat, newest at the bottom: folder and time dim on top, the command in bold, the coloured output below, and the bar at the left (green, red, yellow). The shell's panes are tabs (the phone's way; the terminal uses boxes). Tapping a block selects it and shows Comando, Salida and Repetir. The editor sits at the foot with the folder and branch chips; while a program runs the chip is the program, the border turns dashed and the send button becomes a red stop (^C). The special keys (esc, tab, arrows) have no buttons for now; where they go is still to be decided. The phone shows the workspace highlighted in the terminal; on the real phone Home picks it.
