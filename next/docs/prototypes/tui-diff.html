The diff, in the terminal

Press d in a workspace and its changes fill the pane area: Sin commitear, Commits and General, as on the phone. Click the terminal or tab into it; the keys are on its status bar. The buttons simulate what the daemon would send, and the sizes show the layout changing with the width.

  1. Opening: d on a workspace (the same key as before) shows its changes over the pane area, like Avisos. esc or q closes it and the panes are as you left them. The sidebar stays.

  2. Three views, keys 1 2 3: Sin commitear (opens here), Commits, General (this branch against origin/<base>). The same three as the phone and the old jw. In Commits the left column lists the commits (200 at most); ↵ opens one and ( ) step between commits.
    3. 
      
  3. Left, the tree of changed files: single-child folders on one row, + − totals per folder and per file, a status letter (M A D R ?), ✓ when seen. tab moves focus there; j k move, h l fold and unfold, ↵ jumps to the file.
    4. 
      
  4. Right, every file of the view in one scroll with the current file's header pinned on top. Side by side when the body is 100 columns or wider (180 × 44 here; 140 × 36 shows one column), one column below (s forces one or the other). Syntax colours, the changed words marked, hunks as @@ rows. Under 84 columns the tree hides and tab shows it over the body (96 × 28).
    5. 
      
  5. Seen: v marks the current file and jumps to the next; a seen file folds to its header. The marks are kept by the daemon, so the phone shows the same ones. When a file changes after you saw it, its mark becomes ◌ cambió and it unfolds.
    6. 
      
  6. Live: while Sin commitear is open it refreshes by itself (the daemon looks at git every 2 s only while someone watches it), so you see the agent's edits arrive. Try the button. Commits and General load when opened and with r.
    7. 
      
  7. Limits, as on the phone: more than 2 MiB lists names only; a binary file, a rename without changes or an unreadable one (a symlink) is one line; an origin with no default branch says so in General. Each view has its own loading and error state, so one failing does not hide the others (use the state list above).
