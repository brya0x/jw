Reviewing a pull request: ^␣ R

Click the terminal (or tab into it). Press ^␣ (here: Ctrl+Space, or just R from the workspace list) to open the list of the project's open pull requests; ↵ makes a worktree of the PR, opened as the agent beside the diff. The simulation bar changes what gh answers.


  


  

    
To approve

    
    
      
  1. The list: ^␣ R. Open PRs of this project (the one you are in), most recently updated first, with number, title, author, size and review state. Type to filter (number, title, author, branch). ↑/↓ move; under the list, the selected PR's description and changed files. m with nothing typed shows only the PRs that ask for your review (again: all). o opens the PR in the browser. esc closes. If gh is missing, not logged in, or the project has no GitHub remote, the list does not open and the status bar says gh's reason.
    2. 
      
  2. What ↵ makes. It fetches the PR's head and its base branch, makes the worktree review-<n> (branch review/pr-<n>) at the head, runs the project's setup as w does, and opens it as |agent|diff|: the agent on the left and the diff of the PR on the right, both at once (try tab to move between them, ↑/↓ in the diff to change file). The sidebar shows ⎇ #142 beside the name. A fetch that fails makes nothing and says why.
    3. 
      
  3. The diff is a pane here, not a full screen. It compares against the PR's base (origin/<base>), General scope: that is the PR. This is the point-5 change («the diff view is not full size») shown first in the review workspace; the diff screen of d stays for every other workspace.
    4. 
      
  4. The agent only answers questions about the diff, and nothing is sent for it. It opens idle, as Claude's conversation always does. jwn does not brief it automatically: the field shows a suggested first question in grey (→ or tab takes it, as the suggestion Claude proposes does) and ↵ with the field empty sends nothing. The PR's description, comments and reviews are written to a file in jwn's state folder so the agent can read them when you ask; the agent has no instruction to edit, commit or push. jwn calls gh only to read.
    5. 
      
  5. Picking a PR that already has a review: the head is fetched again and you are taken to it; nothing is sent. A review worktree with changes of yours is left as it is and says so.
    6. 
      
  6. Removing it goes through the same checks as any worktree; a review branch with no commits beyond the fetched head counts as having no unpushed work.
    7. 
      
  7. Not here: the phone (the list of PRs and the review on the phone are a part of their own); commenting on the PR from jwn; sending selected lines of the diff to the agent as a reference (asked for on 2026-10-19, its own part); line wrapping in the diff.
    8.
