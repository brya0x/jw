Three levels: workspaces, panels, terminal

The terminal client works at one of three levels, and the keys mean what that level is about. ↵ goes in, esc comes out, and the status bar always says where you are and what each key does. Click the terminal or tab into it. ? lists the keys of the level you are in.

  1. The file tree (t at the workspace or the panel level; the chip says ARCHIVOS while the keys are in it). A column as wide as the sidebar (28 cells) at the right of the panels, drawn the way the sidebar is: no box, a line between it and the panels (blue while the keys are in it), its name on top, the selected row lit across, and what the marks mean at the foot. It lists the files of the workspace's folder, folders first and then files by name, folders opened and closed in place. j/k move, ↵ or l open a folder or a file, h closes a folder or goes up to the one that holds it, / filters by name over the whole tree, . shows the hidden ones, y copies the path (relative to the workspace), r reads it again, esc gives the keys back to the panels (the tree stays) and t closes it. A click on a folder opens it, on a file opens it. On the right, what git says of each file (M modified, ? not tracked, ◌ ignored: target/ is dim and its folders are listed when opened). A file opens in nvim in a new panel (the panel's program is nvim <path>; when it ends, the shell is there); a .md will be read with its format once the viewer exists, and says so until then. The daemon lists one folder at a time (list_files), so a repository with 50 000 files costs one folder, not all; a folder with more than 2 000 entries is cut and says how many there are. The phone gets the same tree as the screen «archivos» of its prototype (folder by folder, a path of crumbs, .ocultos), which has no editor: tapping a file there is for the viewer.

  2. Level 1 · WORKSPACE (the sidebar is active). j/k move, ↵ goes into the workspace. r renames it, x closes it (and d in that question removes a worktree, as today), o opens a folder, w makes a worktree, s syncs it, d opens its changes. q quits.
    3. 
      
  3. Level 2 · PANEL (the panels of the workspace). h/j/k/l change panel, ↵ starts typing in it. n makes a new panel, r names the panel, f shows it full screen, x closes it. esc goes back to the workspaces. Workspace commands that do not clash (o w s d) work here too, and so do a avisos, m phone and , settings at both levels.
    4. 
      
  4. Level 3 · TERMINAL (typing). Everything goes to the program, esc and ctrl keys included (nvim, claude and the shell use them). The only way out is ^␣, which takes you to the panel level; so the old muscle memory still works: ^␣ x, ^␣ n, ^␣ m are the key you would press at level 2.
    5. 
      
  5. Remove a worktree (x, then d): git is asked what would be lost. With nothing to lose it is one y. With files not committed the box lists them and asks you to type the branch's name before it goes ahead, and then the folder goes by force. The branch always stays, with its commits (the box says how many are not pushed; s pushes them).
    6. 
      
  6. The panels' layout is a tree the daemon keeps for each workspace, so it survives closing the terminal client and restarting the daemon. At the panel level: h j k l go to the panel on that side (by where the boxes are, no longer by number); H J K L swap the panel with the one on that side; | splits to the right and - below; n splits along the longer side of the focused panel (and N does the same with a program); < > make the panel narrower or wider, { } lower or taller (5 % a press, never under 10 %); x closes a panel and its space goes to its neighbour. Dragging a border with the mouse comes with the mouse part. A workspace made before layouts opens with its first panel on the left and the rest stacked on the right, as today.
    7. 
      
  7. Where you are is always visible: the chip (WORKSPACE, PANEL, TERMINAL), a blue border on the active area only, and the keys of the level on the status bar. ? opens the whole list of the level.
    8. 
      
  8. The mouse goes straight in: a click on a workspace opens it (panel level) and a click on a panel starts typing in it (terminal level).
    9. 
      
  9. The list is grouped: each repository's root, then its worktrees indented under it (↳, the dot and the name moved four columns in); a worktree whose root is not open sits under the repository's name; the folders that are not repositories come last under carpetas. The numbers and j/k follow what is drawn; headings are not highlighted. The same grouping is on the phone.
    10. 
      
  10. Panel with a program: n keeps making a shell. N (shift n; from the terminal level that is ^␣ N) opens a menu, «panel nuevo», with shell first and then your programs. j/k and ↵, or the program's own letter, open it in a new panel; esc cancels. The panel is still a shell that runs the program first, so when the program ends you land at a prompt and the panel stays.
    11. 
      
  11. The config is a file: ~/.config/jwn/config.toml with one [[program]] per entry: name, command (a list: the program and its arguments, no quoting to get wrong) and an optional key (one letter; j k n are taken by the menu, and a repeated letter is ignored). The menu follows the file's order. The terminal client reads it and never writes it, and re-reads it every 2 s like settings.json, so editing it is enough. The daemon never sees it: the client sends new_pane with the program it already has.
    12. 
      
  12. Defaults and errors: with no file, or none with a [[program]], the menu has claude; your entries replace that list, they do not add to it. If the file does not parse, the menu keeps the last good list and says what is wrong and on which line, in red, inside the menu. Try the three states above.
