jwn · Sesión ocupada

Cuando otro claude (el normal, de una terminal) tiene abierta la misma sesión, jwn no escribe en ella: la lee, y el campo queda cerrado hasta que el otro se cierre. Así no hay dos procesos escribiendo la misma conversación. Cambia el estado del otro claude y prueba a escribir.

LO QUE CAMBIA

Cómo se sabe. Claude Code apunta cada proceso vivo en ~/.claude/sessions/<pid>.json con la sesión que tiene abierta, su carpeta y si trabaja o espera. El daemon lo mira: si hay un proceso vivo, que no es el motor propio de jwn, con el id de esta conversación, la sesión está ocupada. Vale también para un claude parado esperando tu mensaje.
Qué se bloquea. Escribir y enviar en esa conversación, en la terminal y en el teléfono. Se puede seguir leyendo, desplazar, copiar y abrir lo anterior. No se bloquea nada si la conversación es nueva o la tiene solo jwn.
Qué dice. «solo lectura: otro claude (pid 93269, en jw-wt/next-bootstrap) tiene esta sesión abierta · ciérralo para escribir aquí». Se levanta solo, en unos 2 s, cuando ese proceso termina.
Lo que no cubre. Si jwn ya escribe una sesión y después alguien abre claude --resume con ella en una terminal, jwn no puede impedirlo: eso lo decide el otro claude. Y un registro de un proceso que murió sin borrarlo no cuenta: se comprueba que el pid siga vivo.

PARA DECIDIR

1 · también con el otro parado. Recomiendo que sí: un claude parado en una terminal escribirá en cuanto le hables y bifurcaría la conversación. Pruébalo con «parado, esperando».
2 · el mensaje. Con el pid y la carpeta, para que sepas qué cerrar. En el teléfono es una fila sobre el campo, no un aviso que se va.
3 · si el otro es un motor de jwn. También se bloquea: dos paneles de jwn con la misma sesión tienen el mismo problema.
