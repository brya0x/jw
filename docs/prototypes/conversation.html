claude as a conversation, in the terminal and on the phone

A pane is still a shell. When you type claude in it, jwn starts Claude Code as an engine (it talks JSON) and draws the conversation itself: the terminal in its own screen, the phone flat. Both read one conversation kept by the daemon, so you can start a request at the keyboard and approve it from the phone. Click the terminal, type claude and press Enter; then write anything and press Enter (the story of a turn plays: it reads, asks to edit, asks to run a test). The phone on the right is the same conversation.

  1. The swap. A pane is a plain shell. When what you type starts with claude (also claude -c, claude --resume, claude --model …), the shell integration runs jwn's claude instead of the original. The pane's foreground program is then claude as before, so the sidebar title, the avisos and jwn ls do not change. The terminal client sees it and draws the conversation in its own screen (as it draws the program's screen for full mode today); the phone draws it flat. command claude (or the full path) runs the original Claude Code with its own screen, as today: the escape hatch for what jwn does not draw yet. Try «Type claude in the shell», then command claude.
    2. 
      
  2. The conversation. Close to Claude's own: your messages on a band with ❯, Claude's text with ● (code in cyan), and each tool as one line, ● Read(src/auth.rs), with what it did under it (⎿  Leídas 142 líneas); ^O or a click opens its output. An edit shows its diff with the lines tinted green and red from the theme, the way the shell's diffs are. A line says what Claude is doing while it works (✻ Escribiendo… 8s · ↓ 1,2k), and at the end of each turn the time, the tools it used and the cost. There is no Claude theme to set: every colour is the client's.
    3. 
      
  3. Questions are answered from either screen. When Claude wants to edit a file or run a command, a box opens in the terminal and a sheet in the phone with the same three answers: Sí, Sí, y no volver a preguntar … en esta sesión (offered only when Claude suggests it) and No (Claude is told it was refused). In the terminal: 1 2 3, y a n, or ↑ ↓ and ↵. On the phone the three are big buttons at the bottom, reachable with a thumb. The first answer wins and the other screen says where it came from. Approve once in the terminal and the phone's sheet is gone.
    4. 
      
  4. The line at the foot. Typing never waits: while Claude works, ↵ queues the message («1 en cola», it goes when the turn ends) and esc interrupts (Claude's own cut: «Interrumpido por ti»). The phone's send button becomes the red stop while it works, as for any program. /exit leaves the conversation and the pane is the shell again with a block for it (claude, its time and the id to resume); /clear empties it. The commands themselves are the next point.
    5. 
      
  5. Slash commands. Typing / opens a list over the line (on the phone, above the keyboard; the / button beside the line opens it too) with every command of the conversation, filtered as you type, each tagged with where it comes from: jwn, claude, proyecto (.claude/commands), skill and plugin. The engine names its commands when it starts (115 on this machine, most of them skills and plugin commands), so the project's and your own are in the list. Four kinds: jwn's own (/exit /clear /rename /color /model /effort /mode); screens jwn draws because Claude cannot without its terminal (/help /status /resume /tasks /artifacts /skills /permissions /memory: a list in a box, or a sheet on the phone, with ↑ ↓ ↵; /resume lists this project's past conversations); Claude's that answer with text (/context /cost /usage /recap /goal /mcp /config, and /compact, which shows a line across the conversation with the tokens before and after and drops the context); and the ones that start a turn (/init /review, the project's like /deploy, skills like /jwn or /rust-review, plugin skills like /vercel:deploy: they run as a request and Claude answers, and the line shows the command, not its expanded text). A few need Claude's own screen (/doctor /insights /login /vim…), dim with ↗: choosing one says so and points at command claude. ↑ ↓ move, tab completes, ↵ runs, esc closes. Try /, /co, /tasks, /skills, /status.
    6. 
      
  6. Shell with ! and files with @. Claude's own !command is not shell mode when it is run as an engine (it sends the text to the model), so jwn does it: a line that starts with ! runs as a shell block of the pane, drawn like the shell's blocks, and its output goes to Claude as context with your next message (try !git status; on the phone the ! button turns the line into a shell line). @ opens the project's files as you type (@se), and ↵ puts the path in the line; on the phone the + button opens the same list. Images are attached the same way: pasted in the terminal (button «Paste an image»), from the camera or the gallery on the phone; each shows as [Imagen#1] in the line. In the terminal, ^V pastes an image (as in Claude): the client reads the machine's clipboard and attaches it, so it works where the client runs beside the clipboard and not over ssh, where the clipboard would be the server's; ⌘V is the terminal's own and pastes text. Images are made smaller before they leave: no longer than 1568 px on the long side and as JPEG, which is what the model uses anyway, so a 3,1 MB photo goes as about 240 KB (the line says so; on the phone each attachment is a pill with ✕ above the line). How images and @ reach the engine is for the spec to check with a real Claude.
    7. 
      
  7. Copy and paste. In the terminal, a click selects a message, a tool's output or a diff (a bar lights it), and c copies it, t copies the whole turn and esc lets go; the copy is OSC 52, as the shell's blocks already do, and the mouse can still drag over text as it does in the shell. On the phone a tap selects the same way and a strip over the line offers Copiar, Copiar el turno and Soltar; the text of the conversation can also be selected by long-press as any text. Pasting text of many lines goes in as one paste, not as many Enters. A line says how much was copied.
    8. 
      
  8. Work in the background. What Claude starts and leaves running shows in one place. A subagent is a card, ● Agent(Explore) buscar los usos de verify, with its progress while it works (⠹ Grep · 2 herramientas · 14k tokens · 3,1 s) and its totals at the end; ^O (or a click) opens its steps, which are the tools it used (its text is not streamed by the engine). A shell in the background, a monitor (each line it prints is a note, and each one starts a turn by itself, so Claude answers without you writing) and a /loop or scheduled task are rows of the same list. In the footer, ⚙ 2 counts what runs; click it, press ^B or type /tasks to open the list and x stops the row you are on. On the phone the pill ⚙ 2 in the header opens it as a sheet with a ■ per row. Claude's task list (TaskCreate) is a strip at the top, ☐ 2/4 tareas, that ^T or a tap opens. Because the engine lives in the daemon, all of it keeps running when the terminal client is closed. Try «Background work».
    9. 
      
  9. Questions and pages. When Claude asks you to choose (its question tool) the same box and sheet as a permission opens, titled «pregunta», with the options as numbered rows or big buttons, and the sidebar and the phone show ?; your choice goes back as its answer. When Claude publishes a page (Artifact) it asks first, as it is public, and then shows ● Artifact(Informe de pruebas) with ↗ abrir en el navegador (a button «Abrir» on the phone); /artifacts lists the ones of the conversation. Try «Claude asks a question» and «Claude publishes a page».
    10. 
      
  10. On the phone, with one hand. Everything that needs an answer (permission, plan, question) is a sheet from the bottom with 48 px buttons, the main one first. The line at the foot is kept light: only +, the field and send. Above it, a row with two small pills at the left, the model that is running with its mode (● sonnet-5.5 · manual; it opens the conversation's settings: name, colour, model, effort, mode) and the branch, and at the right the +, exactly over the send button so the thumb finds both in one column. + opens a short list (file, photo, gallery, commands, shell); typing / or ! as the first letter does the same without it. The header carries the ⚙ pill while something runs. A turn that finishes or a question that waits reaches the phone as an aviso even with the app closed, because the engine runs in the daemon.
    11. 
      
  11. Each conversation has a name and a colour. The name starts as the first words of your first request (the id until then) and you change it with /rename or by clicking the title (on the phone, the tab opens the settings sheet). It is what Home and claude --resume show, and jwn passes it to Claude (--name) so a plain terminal shows it too. The colour is only an accent of the chat: one of the theme's six (blue, green, yellow, red, magenta, cyan), never a free colour, so it reads in every theme. It tints the pane's border and title, the ❯ marks and, on the phone, the tab and the selected options. /color opens the six, /color red sets it. Claude Code has --name, /rename and /color of its own; here they are the conversation's, kept by the daemon, so they are the same on both screens.
    12. 
      
  12. Model, effort and mode. The footer of the conversation has two ends: at the left the mode and, while something runs in the background, the ⚙ 2 counter; at the right the model. Nothing else: the context, the cost and the limits are not drawn there (the cost of each turn is on its closing line, and /context, /usage and /status show the rest, effort included). A click on the mode or the model opens its list; the keys are /model, /effort and ⇧tab for the mode (the four of Claude: manual → accept edits → plan → auto). On the phone, the pill above the line shows the model and the mode and opens a sheet with all of it, plus the name and the colour. Model and effort apply from the next message; the mode applies at once. In plan mode Claude reads but does not edit: it ends with a plan and a question with three answers (approve and edit without asking, approve and ask for each edit, keep planning), the same question on both screens; approving changes the mode (try «Plan mode»). accept edits stops asking for edits (commands still ask). auto lets Claude's own classifier decide what is safe: edits and ordinary commands run without asking, and anything it holds back reaches you as the same question (try it: «Auto» in the phone's sheet or ⇧tab three times). The others Claude has (bypassPermissions, dontAsk) are not offered. How a change reaches Claude (a control message, or restarting the engine with --resume) is for the spec to settle; the person sees no difference.
    13. 
      
  13. Avisos come from the conversation itself. A question shows ! (red, «pide permiso») on the workspace and on the pane, and a finished turn shows ✓ until you look. Today they come from hooks only when the daemon started claude; here they come from the events, for every claude you type. «Seen» is shared as everywhere else.
    14. 
      
  14. When the daemon restarts the engine process goes with it, but the conversation is Claude's own transcript on disk: a line says el daemon se reinició, and the next message resumes it (--resume, «retomando conversación…» for a moment) with everything above it kept. A turn that was running is cut, as a command is in the shell.
    15. 
      
  15. Outside the terminal client (an ssh session, a plain terminal): the same claude draws a minimal version of the conversation as lines in the terminal (the button «Show the plain-terminal version»): no boxes, the question as a numbered prompt. The conversation is the daemon's, so it is the same one.
    16. 
      
  16. Not here yet (use command claude), besides what the engine cannot do without a screen: workflows, sending a command that is already running to the background (^B here opens the list), # notes, and rewinding the files (/rewind). codex is a later part with the same mould.
